# 质量验收与评委本地运行入口

用户要求按提交要求持续改进。先补现有官方样本判卷，修复质量，再提供本地运行和自动报告。GitHub 推送改由用户手动执行；本轮不调用推送、登录或浏览器界面。

## 验收目标

基础交付包括方案、可运行代码、实验报告、复现步骤和 AI 协助说明。客观门槛按用户提供的题面截图：知识识别至少 70%，条目准确率至少 85%，随机十条来源至少 8 条可核查。三项须同时达到，才讨论主观分的竞争力。

本地 Agent 自测需与正式评测、人工确认分开。目标为形成可复现的达标证据，不能保证正式评测分数或获奖。缺少完整判定时指标为空；失败、未发布和未知调用均保留。

## 当前基础

- 官方四阶段的 baseline、artifact-only、verified 已有 12 份旧版本原始输出，v2 判卷表尚未完成。
- 新来源审计 v2 的三任务没有正式发布结果，保留实验开关。

## 方案选择

先交付本地评委运行包。复用标准库 CLI 与已有模型适配器，新增一条运行命令及离线 HTML 报告。评委提供样本和自己的模型配置。线上服务会增加部署和鉴权，不是题面本地评测的前提；Word、在线 Docs 导出排在质量和本地复现之后。

质量改进新增阶段级 grounded 模式，先用两个模型步骤验证“来源编号绑定、字段独立支持、全文复核”。保留旧模式作为对照，避免把已知失败的整需求审计协议切成默认。完成独立验收后再决定推荐模式。

## 质量机制

模型依据原始对话与最终产物提出条目，证据选择真实整行编号；程序填入逐字原文和位置，不要求模型抄写引文，也不暴露句片别名。复核同时读取完整原文和候选，修订最终条目及争议状态。

理由、边界仅表达原文支持的内容。禁止由一个前提反推未经证实的适用范围；已知解释与剩余未知都要保留。字段不能借另一字段的引文。明确用户归因须引用真实用户；决定须核对用户确认、后续纠偏及产物采纳。原文明确陈述的既有系统事实也可提取，不能把所有 Agent 发言一刀切拒绝，更不能把其提议升级为决定。程序检查编号、必要实现符号及字段对应，语义真伪仍靠独立判卷。

两个正常调用，每步最多一次完整 JSON 协议修复。第一步生成条目与未决项；第二步根据完整原文修订，并对每个字段按最终数组下标给支持判断。模型不需额外输出庞大的逐候选审计表。无效 JSON、认证、断流或截断不自动重发。重复输出目录拒绝。修复不得改写原材料、参考或历史预测。

阶段模式单独名为 grounded。保持 legacy MODES 不变，阶段 CLI 使用扩展 STAGE_MODES；整需求命令继续限定原模式，不静默接受新阶段模式。正常输出保留现有 JSON 条目结构，增加来源协议标记、字段复核与必要符号证明。保存校验从真实来源重建完整引文及证明；删除证明或伪造格式须拒绝。

模型输入采用阶段来源列式表，完整保留原 prompt 的 source_id、role、message、text 与文件映射；来源仅使用原始整行编号，不暴露句片别名。先收集不存在的编号统一报告，再展开证据。展开总量有明确上限，拒绝异常膨胀而不截断业务内容。

旧阶段三模式和整需求接口保持可用。grounded 的提示、来源协议和证明单独绑定版本；新模式不会让整需求命令静默退化为未复核提取。

## 评委入口与报告

新增 `decision-memory run --dataset 样本.zip --config 模型.toml --output 新目录`，明确模式与版本。先离线检查全部输入和配置，再执行提取。运行只读取题目给定的对话和产物，不读取评测标注。

输出结构化结果、逐样本 Markdown、自包含 HTML、批次 JSON 和可读运行报告。HTML 可查看条目及真实原文位置；输入、输出、错误均需转义。报告区分完整成功、部分成功、失败及执行未知，记录模型、代码摘要、输入指纹、调用数、耗时、token 和可得的金额；缺单价时金额为空。

评委运行不自动给自己计算准确率。自测评分是另一个流程，只有评分侧读取固定标注。人工复核和正式成绩在所有报告中单列。

MyToken 示例只存环境变量名。用本地 HTTP 实测自定义头与脱敏；使用用户已授权的真实网关验证端到端。没有 MyToken 真实凭证时不宣称其积分服务已实测。

## 评测与预算

首先在新目录匿名判卷已有十二份输出，原评分与原参考不改。每个阶段独立上下文，不读取其他阶段、方法映射或成本。阶段参考有问题时单独记录，不能为了当前输出改参考；后续预测前冻结纠正版本。

真实新对照先冻结代码、配置、输入、参考和选型规则。对同一官方开发集比较 baseline、artifact-only、grounded；另使用未参与修复的需求验收。已经用于修复的保留需求归入开发，不再标为盲测。

每轮最多 32 次实际 HTTP，并发不超过 2；已知输入达到 500,000 或输出达到 100,000 token 后停止启动新任务，在途请求可完成。单任务最多 2,700 秒。未知执行、认证或计费错误停止队列，不换目录盲目重发；每个调用保留可核实回执。付费探针不另行添加。

主选择先要求三项门槛和稳定输出，再比较同口径分数、样本耗时及成本。只对双方正式输出作主质量对照；草稿只诊断。来源抽查在预测固定后按预定种子抽取，所有条目的引用支持也同时报告。

进阶消融保留“产物单独”与“对话加产物”比较，补真实关闭来源机制的内容对照；不靠删除展示字段冒充消融。关闭来源的诊断不作为可提交版本，内容指标与来源指标分开，不能混写成比赛分数。

## 交付

按代码评审、测试、真实自测、文档和源码包依次验收。原始会话、题面材料、固定标注、运行输出和凭证留在本地忽略目录。公开仓库包含通用实现、虚构样例、配置示例和汇总。只在本地提交，最终给用户手动 push 命令。
