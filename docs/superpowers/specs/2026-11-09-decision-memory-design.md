# 研发阶段决策提取 CLI

用户已在对话中确认实施 2026-11-09 提出的方案。本文件记录该方案及实现时的具体选择。

## 目标

读取一个已完成阶段的原始对话及最终产物，输出带字段级证据的有效决策、理由和适用条件，以及独立的待确认项。服务于下一阶段 Agent 交接和命题 07 的样本评测。

## 方案选择

保留单次模型提取作为 baseline。主方案采用决策变化识别、条目生成、全文证据复核三个步骤，检验多步骤的质量及成本收益。模型负责语义识别，程序负责来源编号、精确引用校验、输入隔离、格式验证和结果持久化。

Python 3.11+ 标准库实现，无运行时第三方依赖。支持配置的 OpenAI Chat Completions 兼容 HTTP 接口，Mytoken 的实际入口和鉴权方式通过官方资料确认后适配。凭证从环境变量读取。

## 输入和输出

- 单阶段输入为一个对话 Markdown 和一个最终产物 Markdown。支持官方 ZIP 与解压目录的四组样本发现。
- 推理仅加载指定阶段的两份材料。评测标注由独立评测命令读取。
- 每个非空原文行有稳定证据编号、源文件标识、行号、消息编号、原文。保留原始文件 SHA-256，结果可验证输入版本。
- 条目包含 conclusion、reason、boundary 三个带 text/evidence 的字段。缺失理由或边界明确为“未说明”，证据为空。
- 每个证据为 source_id 和逐字 quote。程序映射为文件、行号和消息编号，拒绝不存在、空白、越界或不匹配的引用。
- 最终有效条目、待确认项、审查警告分开存放。决策轨迹作为 audit 保留，标注 active/superseded/pending/conflict。
- 输出 JSON 和便于交接的 Markdown。结果带模型、用量、耗时、可选成本估算及校验状态。

## 调用与失败

设置请求超时、有限重试、输入大小上限和输出 token 上限。HTTP 429/5xx 等暂时失败可重试，认证失败立即报错。JSON 格式及引用错误最多修复一次。修复后仍失败则该样本失败，CLI 返回非零状态，批处理继续处理其他样本并记录失败清单。

输出原子写入。批处理默认拒绝覆盖已有结果，显式 resume 只复用输入指纹、模型配置、模式、提示词版本完全匹配且校验通过的结果。失败和复用情况均写入汇总。来源文本只作为待分析数据，不作为工具操作指令。

## 评测

提供可编辑的人工评测清单，按样本列出有效知识、过程噪声、引用结构及实际模型结果。计算已填写人工 verdict 的 precision/recall 和来源核查比例，同时显示未评条目数。未评结果不计为通过，官方指标细则未明确前标记为本地自测口径。公开 ZIP 的两个标注文件作为原始参考保留，跨阶段标注需要人工核对。

比较 artifact-only、baseline 和 verified 三种模式。同模型、同样本分别记录耗时、tokens 和费用。补充数字变化、否决后修订、字段缺证据、跨阶段泄漏、模型错误和断点恢复的回归测试。

## 验收和交付
