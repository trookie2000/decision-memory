# 来源编号证据与字段检索 v2

用户要求直接完成修复、对照、保留材料验收和交付。现有 v1 协议错误已修复；真实试点仍有错抄引文、字段拼入无依据实现细节、遗漏产物约束的问题。本轮保留旧模式，增加主动开启的 v2，并按固定门槛决定是否推荐使用。

## 方案与边界

模型只选择真实来源编号，程序从不可变索引填入原文。保留现有角色准入、历史更新、未知保留和候选覆盖校验。在最终复核前，程序按字段整理相关来源与缺少依据的代码标识符。整份输入采用无损列式 JSON，减少重复元数据。

不自动猜测缺失来源，不用模糊匹配修复引文，不把词面匹配当语义支持。额外投票或新增常规模型调用会增加成本，本轮继续两步正常调用，每步最多一次完整 JSON 的协议修复。旧 verified、artifact-only 和审计 v1 行为不变。

## 输入与证据协议

- 入口为 `requirement extract --mode verified --evidence-audit v2`。其他模式和超出 256 个覆盖候选时，在模型请求前拒绝。
- 列式输入保存全部来源字段：source_id、node_id、node_order、file、line、role、message、text。列名只声明一次，每行值可逐字还原原索引。未知角色保持 null，不删材料、不裁剪业务内容。
- v2 模型输出的 evidence 为来源编号字符串数组；单个目标证据为一个来源编号。每行保留原来源编号；含多个句片的行可增加 `#C001` 等程序编号，只暴露在原行内唯一的连续句片。未知、重复、空白、对象式或伪造编号均拒绝。程序从编号表填入整行或唯一句片，不选择首个模糊匹配。
- 事件的新增、更新、合并、失效和问题都采用同一编号协议。展开后继续执行节点顺序和现行知识重放。
- 理由未知清单由程序分配稳定 G001 等 gap_id。模型只返回 gap_id、状态、关联知识、unknown_text、来源编号和说明；程序填入声明的 source_id/quote，继续执行原有未知保留校验。
- 证据审计的 direct/proposal/confirmation、用户归因和覆盖目标也用编号。覆盖 reason_check 目标使用 gap_id。v2 evidence_focus 必须为空，存储位置由实际选中的唯一原文计算。业务与排期同处一行时，可选择业务句片，避免把无关上下文当成知识。

## 字段检索与必要检查

第一步仍由模型生成候选事件。第二步同时读取全部原材料、候选事件和程序生成的字段线索，不额外调用模型。

字段线索只来自 sample.catalog：当前引用、同一消息内的相关行、代码标识符命中及稀有中文二元词的检索结果。每个字段最多给 6 条建议，排除该知识节点之后的来源。建议不是证明，复核者须独立判断每项文字是否受其本字段的来源支持，不能跨字段借用引文。

必要检查覆盖大小写混合的函数/变量名、带点或命名空间的标识符、包和代码路径。避免把普通英文名词、日期、小数或常见协议缩写全部当成实现符号。字段明确写入的实现符号必须出现在该字段的实际引文中；缺项汇总给同一步的有限修复。这个检查不声称证明业务语义，也不替代角色、否定、范围和时序复核。

候选覆盖沿用 evidence-v1 的可重建规则，但模型输入只提供候选编号、来源编号和声明片段。最终仍保存完整可重放审计，不以候选完成数冒充召回率。needs_review/partial/unclear 仍不可由格式修复清除。

## 持久化与兼容

- v2 使用外层 schema_version=4、evidence_audit_version=v2、model_evidence_format=source-id-v1、source_format=columnar-v1。
- 保存结果的事件和引文都是程序展开后的完整格式，增加 literal_grounding 的规则、输入摘要及逐字段符号绑定。模型不得填写该证明。
- run_signature 和 prompt_hash 绑定 v2 提示、编号协议、输入格式及符号规则。原有 v1 hash 和输出保持不变。
- 离线 validate 重放事件、重建编号表、核对引用、字段复核、符号证明和既有角色/覆盖审计。删除新证明、改引用或简单降级 schema 即使重算外层摘要也拒绝。
- 沿用原子私有写入、每次模型响应及错误回执、自包含 HTML、认证回显拒绝。无效 JSON、截断或网络未知不自动重发。

## 验收与发布

先做合成协议与本地 HTTP 回归，再冻结实现、配置和材料。已知 REAL-02 仅作为开发集；另由隔离的材料整理者准备两份未参与本轮实现的历史需求及固定参考，独立复核参考后才预测。原答案和旧分数不改动，参考不进入预测进程。

有限试验最多 5 个任务、20 次实际 HTTP 尝试，并发不超过 2。已知用量达到输入 500,000 或输出 70,000 token 时停止新任务；在途请求可完成。单任务最多 2,700 秒。任何传输执行未知、认证/计费错误或配置拒绝都停止后续队列，不换目录重发。

逐条内容判断、各字段引用支持、参考覆盖、未知保留、完成率、调用和 token 分开报告。只比较两边都发布的同一需求；草稿另作诊断，空输出不能靠拒绝全部知识获得高质量结论。人工核准仍待完成，不能换算为正式比赛成绩。

只有开发与保留需求的内容、引用和参考覆盖均不低于固定对照，且没有新增未知丢失、范围扩张或明显成本退化时，才推荐 v2。否则保留为主动开启的实验功能，明确未达标原因。最后完成代码评审、全部测试、使用说明、可复现源码包和可用认证下的推送，不声称认证失败的推送已完成。
