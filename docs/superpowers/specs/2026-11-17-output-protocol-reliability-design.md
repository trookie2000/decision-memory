# 输出协议与失败诊断修复

用户要求直接修复并持续验证 CLI 的竞赛表现，采用当前 Python 实现，在现有开发分支内完成。上一轮真实需求试点暴露了两类输出问题：无依据字段的句号标记导致结构失败；严格 JSON 解析失败后缺少安全的原响应和准确的阶段状态。

## 方案选择

采用窄范围格式规范化、独立失败状态和可追溯的本地诊断。继续执行严格 JSON、完整引文、字段支持和未知保留规则。通用容错 JSON 解析会掩盖截断或额外文字，不用于审计模式。依靠付费重试也不能替代诊断。

## 行为

- reason/boundary 整字段为 `未说明。` 或 `未说明.` 且 evidence 为空时，规范为 `未说明`。保留字段级 `protocol_normalization`，包含原文和规则 `unstated-punctuation-v1`；事件、当前知识和离线重放均保留这份记录。结论或待确认事项不得使用未知占位，带证据的未知占位仍拒绝。其他业务文字、复合未知及引文不规范化。
- 已有规范化记录必须与规范后的字段、原始标记和规则一致，重放时不得静默删除或伪造业务变更。旧结果没有这份可选记录时行为不变。
- 模型内容解析失败时，异常可携带安全的响应内容和结构诊断。诊断包含固定错误类别、结束原因、内容长度、SHA-256、围栏标记和可得的 JSON 错误行列。HTTP 头、环境变量值、API Key 不进入公开调用记录或错误文本。
- 审计运行在本地独立 run 内保存解析失败内容，文件权限为 0600。写入前去除本次认证头及凭证值。状态中只引用文件名和安全摘要，不嵌入响应内容。
- 传输已完整返回、但解析失败时，provider_execution 为 response_received，failure_phase 为 parse；网络执行未知仍为 unknown。结构校验失败记录错误，且保持原来的单次结构修复上限。解析失败、截断、网络未知均不触发自动重发。
- 严格 JSON 的语法门槛不变。真实复测使用预先固定的 json_mode=true 配置，保持新旧配置一致；网关拒绝参数或执行未知时停止，不自动切换配置或重发。

## 验证

先用本地 HTTP fixture 复现收到完整响应却记录 unknown、缺少原内容、认证值回显、句号占位和重放问题，再修复。运行全部单元及本地 HTTP 集成测试。保留旧试点、旧 Mario 评分、原响应和原发布率。

新真实试验先限一例开发集的新旧对照。预测前固定新实现、配置、材料、参考、预算和停止条件；独立语义判卷。只有两边均发布时比较成对质量。该例已经用于排障，不作为保留集或正式成绩。
