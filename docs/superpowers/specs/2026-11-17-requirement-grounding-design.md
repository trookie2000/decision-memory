# 需求级理由与未知信息复核设计

## 问题和目标

六例独立复核发现两类错误：引文真实存在，但不支持理由；模型说明了调整的理由，却遗漏具体参数取值的理由未知。用户已要求修复这两类问题，并保留旧预测、gold 和 Mario 原评分。

默认需求级 `verified` 目前有两次模型调用。第二次只返回整份修订事件，程序无法检查每个字段是否审过，也无法检查原文明说的理由未知是否处理。

## 方案

采用结构化复核，继续使用现有第二次调用。复核输出包含修订事件、未决项、说明，以及 `grounding_review`。程序重放事件后，要求每条当前知识的结论、理由和边界均有对应判定。

只改提示词难以检查漏审；增加独立的第三次调用会提高正常调用数。本次保留两次调用，将复核结果变为可校验的协议。语义判断仍来自模型，结构校验通过不代表人工认可。

程序从原始来源收集明确提到原因、理由或依据未说明的声明片段，作为复核清单。模型必须逐项说明：未知仍有效并保留、后续节点已解决或取消、内容不属于当前可复用知识。

片段按句号、分号等标点划分，用来源编号和完整片段共同标识。未知正文及其证据都须明确含有未知含义，不能只在普通事实旁附 retained 标签。同一行中的独立声明允许不同处理，不因共用来源行就错误合并。

保留的未知必须关联当前 `knowledge_key`。完整理由未知时使用原有的 `reason=未说明`；部分理由已知时，理由正文同时保留已知解释和具体未知，并引用两部分原文。例如：已经知道阈值过高而下调，但为何恰好选新阈值仍未说明。

后续解决或取消必须提供更晚节点的证据。范围外内容必须给出原文依据和具体说明，不能用空判定跳过。这里的语义仍需评审者核对，程序不使用相似度猜测两条业务规则是否相同。

## 实现边界

- `verified` 返回需求级结果 schema 2，并保存复核清单及其当前知识摘要。缺字段、重复判定、错误来源、漏处理未知或残留 unsupported 判定均拒绝保存，沿用每步最多一次格式修复。
- `baseline` 和 `artifact-only` 保持正常一次调用，明确标为未做字段语义复核。提取说明也要求保留部分理由未知，但不把提示词要求当作验证完成。
- 新结果离线校验要重放复核协议。旧 schema 1 结果继续按原规则校验，不追认新检查，不改旧文件。
- 结果 Markdown 展示复核状态和未知处理，便于评审追查。
- 新模块加入冻结实现清单。实现变化后使用新输出目录；旧批次仍绑定原来的代码版本。
- 不修改阶段级算法、评分口径、参考答案、模型配置或任何旧运行产物。不自动训练模型，也不新增依赖。

## 验收

脱敏测试覆盖错误理由引用的修正、部分理由未知的保留、漏审拒绝、伪造或越序证据拒绝、旧结果兼容和保存后复核。测试只替代外部模型回复，事件重放、来源校验和存储使用真实代码。

正常需求级 `verified` 仍是两次调用，格式修复最多使每步增加一次调用。没有可用凭证时先完成离线回归，并明确真实模型效果尚未重测，不能直接沿用旧分数宣布改善。
