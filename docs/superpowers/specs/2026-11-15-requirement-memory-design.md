# 需求级知识提取与评分校验

## 目标与范围

本轮按用户已确认的方向推进：一个已完成需求可以包含多个有序节点。CLI 输出当前有效知识，保留修改和失效记录，每个字段都能回到原文。现有阶段接口及历史结果继续可读。

先交付本地文件形式的结果。跨需求共享知识、检索服务、多轮投票和独立知识库平台留到后续实验。模型语义判断与代码格式校验分别报告。单元测试不代表模型提取质量已经达标。

## 方案取舍

考虑过三种做法：分别提取后直接拼接、一次处理整个需求、逐节点提取再做语义合并。直接拼接无法处理推翻与重复；逐节点提取会重复传入材料，并增加调用。首版选择整体读取需求，模型给出有证据的变更操作，代码按顺序重放操作。

阶段提取保留原行为。需求级 `baseline` 和 `artifact-only` 各做一次抽取；需求级 `verified` 再做一次原文复核。格式修复仍受现有 `checked_call` 的两次上限约束。暂不引入投票。

## 输入与来源

新增 `requirement inspect/extract/validate`。输入二选一：

- `--dataset` 加 `--requirement-id`：从现有官方 ZIP 或目录读取该需求的分析、设计两组材料。
- `--manifest`：JSON 文件包含 `schema_version=1`、`requirement_id` 和按顺序排列的 `nodes`。

每个节点包含唯一 `id`、非空 `stage`、相对路径 `dialogue` 和 `artifact`。节点阶段可以是分析、设计或编码等标签。清单最多 64 个节点，单份输入最多 2 MB，整个需求最多 8 MB。清单路径、符号链接不能越过清单目录。未知字段报错，避免将参考答案等字段误当输入。只读取清单列出的两类材料，不搜索评测标注。

节点顺序就是有效先后；没有时间戳时不生成日期。来源编号采用 `D.<node-id>.<原始行号>` 和 `A.<node-id>.<原始行号>`，保留文件、行号、消息编号和角色。输入指纹包含节点顺序、阶段和文件摘要。节点顺序改变也会使旧结果失配。

## 有证据的变更操作

模型返回 `events` 和 `open_questions`。每个事件包含唯一 `id`、稳定的 `knowledge_key`、`node_id`、`operation` 和 `previous`。操作有四种：

| 操作 | 含义 | 必要数据 |
|---|---|---|
| `add` | 新增当前有效知识 | 完整 `item`；`previous=null` |
| `update` | 细化、替换或重新确认已有知识 | 完整 `item`；引用同一知识的当前事件 |
| `invalidate` | 让已有知识失效 | 原文 `evidence` 和非空 `note`；引用当前事件 |
| `merge` | 同一事实补充来源，保持文字不变 | 按字段组织的 `evidence`；引用当前事件 |

`item` 沿用结论、理由、边界及引文格式，可带现有 `kind`。同一议题但适用对象或范围不同的规则，应使用不同的 `knowledge_key`。程序验证显式关联，语义上是否相同仍需模型与人工复核。

事件按节点顺序排列。事件不能引用未来节点的材料。新增和更新的结论、失效依据、合并依据至少有一处来自事件所属节点。代码拒绝重复 ID、未知节点、错误前驱、跨知识更新和用合并操作改写正文。理由或边界未说明时保持空证据。

代码生成当前 `items`、`memory_index`、`history` 和 `relations`。当前条目只来自仍有效的知识。历史记录保留旧版本与失效依据；关系分别表示更新、失效和补充支持。未决事项进入 `open_questions`，不能靠一次未确认的提议覆盖当前知识。

复核模型可以修订完整事件流，之后重新校验和重放。只保留最终有效事件流，不把草稿当作评分答案。每个结果保存代码版本、提示词摘要、模式、模型参数摘要、原始输入摘要和真实用量。

## 保存与恢复校验

结果仍保存为 JSON 和 Markdown，已有输出不覆盖。需求级 Markdown 先列当前知识，再列未决项和明确标注的历史记录。

离线校验检查输入摘要、结果摘要、来源位置、事件关联和重放后的当前知识。即使文件重新计算了摘要，也不能让当前知识与事件重放结果不一致。`artifact-only` 的事件和未决项只能引用产物。

## 评分可信性

评分器先检查预测的原文位置和保存摘要，再把实际源材料交给评分模型。评分必须同时满足：

- 输出 ID 和参考 ID 各自一一对应，不能重复或遗漏。
- `full/partial` 必须指向存在、有效、引用支持且匹配该参考的预测。
- `missing` 的支持列表为空；预测的 `matches` 与参考支持列表双向一致。
- 每个判断有非空说明；无效条目不能匹配参考。

默认以完整覆盖计算保守的本地识别率和阈值换算。部分命中按 0.5 计算的指标单列为辅助值，不声称出题方规定了该权重。所有报告继续标记为本地自测。

需求级结果直接按 `requirement_id` 分组。单个评分范围内不混合需求级与阶段级预测。按需求评阶段结果时，必须包含该需求的全部输入阶段。预测、原文和评分配置的摘要进入新报告，历史报告不改写。

## 验收

以虚构的两至三个节点需求验证新增、更新、失效、合并、未决项和不同范围共存。补充未来引文、错前驱、路径越界、顺序变化、结果篡改、重复评分 ID 和矛盾覆盖等失败案例。通过本地 HTTP 测试覆盖完整 CLI 的请求和文件输出，真实模型效果另行报告。

保持 Python 3.11、标准库依赖和当前分支修改归属。本轮不操作用户键鼠，不向未授权的群或人员发送消息，不把内部原文、凭证和运行记录加入公开仓库。
