# 需求输入与状态改造记录

2026-11-17，工程版本 0.4.0。本记录区分已实现的程序行为、自动回归证据和仍待测量的模型收益。历史实验目录中的 v0.5 等名称是实验标签，与包版本编号分开。

## 本轮问题与实现

命题方补充说明：目录结构不变，除已给出的材料外，还可能包含数据口径等额外文件。因此不能将输入写死为两份文档，也不能把额外文件的排列位置当作新阶段。

| 问题 | 实现 | 可核查产物 |
|---|---|---|
| 额外文件被当作后续节点，产物目录中的额外文件自动获得产物身份 | 文件类型 `dialogue/artifact/supplement` 与阶段 `node` 分开；补充材料 `node=null`，保留原来源编号 | `sources.py`、`inspect` 的 `documents` |
| 默认入口仍按阶段拆分 | `inspect/extract/batch` 默认需求级；保留 `--unit stage`；独立对话/产物文件参数仍按阶段；验证旧结果按其 stage 自动选择 | `cli.py`、命令行集成测试 |
| 早期阶段产物被永久视为有效 | 模型提供稳定 topic/scope 与状态；代码检查同议题、同范围内的后续明确依据，允许早期产物失效 | `memory.py`、`decision_history` |
| 同一行多个事实被一起删除 | 以逐字引文片段为单位检查失效；包含新旧依据的变更条目保留 | 同行新旧值回归、变更条目回归 |
| 无法解释为何失效、是否曾被确认 | 历史保留原证据、后续依据、原因及其证据、原节点、解决节点；原因缺失写未说明 | JSON 与 Markdown 决策历史 |
| 程序怀疑被写成业务未决项 | `review_queue` 记录材料冲突、无依据的替换和相关候选；`open_questions` 只用于原文明示的业务待定事项 | 分离输出、`checks.requires_review` |
| 引用修复发生但未显式记录 | 决策轨迹的保守修复进入 review_notes/checks；不补写原因或替换依据 | 修复回归 |
| 本地运行日志进入候选提交、锁文件版本过期 | `.gitignore` 排除 `.docs-cli/`；用 `uv lock --offline` 将锁文件同步至 0.4.0 | 333 份日志保留本机；`uv lock --check --offline` 通过，依赖列表未增加 |

额外文件仍只支持 UTF-8 Markdown。本轮没有自动推断未知文件所属阶段，也没有推断真实业务生效日期。补充材料中的角色标记不提升整份材料的权威级别。

代码验证的是引用存在、已提供的议题/范围关联及节点顺序，不能凭此证明模型对语义的判断正确。无依据的轨迹进入核查队列，不能据此宣称已完成语义核验。

## 思路来源与预期影响

- 输入模型与优先级直接来自命题方文件格式说明，以及本项目已发现的“额外文件被排成后续节点”和“产物永不失效”两处实现问题。
- 显式保留替换关系与历史，借鉴 [Mem0 的记忆更新操作](https://arxiv.org/html/2504.19413v1) 和 [Zep 的事实有效期](https://help.getzep.com/v4/facts) 思路。本实现只记录已知阶段及本次运行时间，并非完整双时间系统，也未实现 Mem0 的整套操作分类。
- 逐字片段过滤、业务未决事项与程序核查分开，是为本任务设计的工程约束；完整语义去重和字段独立验证仍是后续工作。

预期减少旧方案误提、错误覆盖和未决事项污染，主要影响准确率与跨节点状态正确性；补充材料有机会补足口径与边界，从而改善识别质量。当前仅验证了程序机制，尚无新版本真实分数，不能承诺提分。

## 验证方式

新增自动回归覆盖：早期产物被后续决定替换、补充材料不能越权、补充定义可正常使用、不同范围不互相替换、同一行的新旧事实分开处理、新旧证据共同支持变更、冲突进入独立队列、待定事项被后续解决、直接否决无需新方案、引用保守修复，以及保存结果的历史/队列重放。命令行使用本地 HTTP 模型替身，检查默认需求级输入、额外文件进入请求、评测答案隔离和旧阶段验证兼容性。

```bash
python3 -m unittest discover -s tests -v
python3 -m decision_memory inspect --dataset data/public-samples.zip
```

本机验证目录：`runs/v0.4-input-state-20261117/`。全量 167 项测试通过（其中新增 14 项状态回归和 1 项需求级命令行集成测试）；`git diff --check` 通过。官方附件离线检查得到 2 个需求，每个包含 2 个阶段；G002/G003/G004 共 157 份受保护运行文件重新通过离线审计。原始预测、参考、评分和源材料保持原样。

真实效果验证必须新建输出目录：相同冻结输入、相同抽取/评分模型和口径，比较旧版本与新版本的有效条目、完整/部分命中、失效状态错误、未决事项准入和 token/耗时。新增补充材料压力样本另行固定，不能混入旧测试集后仍沿用旧分母。

当前进程未继承模型凭证，本轮没有真实模型运行或 DeepSeek 新评分。测试替身只验证工程链路，不作为模型质量证据。

## 事件策略补充材料整合（工程 0.4.2）

0.4.1 检查点已提交为 `e017ca7`。本批在其基础上将目录/ZIP 中的额外 Markdown 接入 `RequirementSample` 事件策略，显式清单增加可选 `supplements`。补充文件使用独立分组来源编号及 `document_type=supplement`，节点和顺序为空；与 grounded 共用输入描述，但保留各策略真实的来源编号和重放方式。

无节点 `add` 可新增背景事实，`merge` 只增加证据，`update` 仅补齐现行知识原为未说明的理由/边界，保留所有已有确认文字及证据。拒绝无节点失效、恢复失效知识，以及以补充文件加旧确认借证替换已知字段。正式节点的本节点依据和禁止未来引用继续有效。明确用户归因必须有该字段的正式用户证据。

默认字段复核、理由未知处理、审计 v1/v2、来源编号展开、字符定位及 HTML 均接入无节点来源。审计使用独立的 `supplement_direct` 准入，补充正文进入覆盖清单，不能借角色标记获得正式确认。新结果绑定 `event_protocol=typed-material-events-v1`、`input_contract`、文件摘要及有效提示词指纹。旧无补充输入的摘要与审计提示词保留；CLI 校验及数据集评分按旧结果声明的节点对重建，不声称旧结果读过额外文件。包与锁文件升至 0.4.2，不增加依赖或正常模型调用数。

思路来自命题方“文件不限于示例两份”的输入说明，以及已合入的事件重放和共用输入契约。无节点状态及保留正式确认的约束，是针对本项目的保守工程设计，不宣称采用了新的研究算法。预期减少补充口径遗漏、时间误推和错误覆盖；必须通过冻结样本的完整覆盖、字段支持、发布率与成本验证，程序测试不能证明提分。

含全局补充文件的整需求/逐节点 `compare` 暂在付费调用前拒绝：尚未定义背景文件在各阶段的公平分配，不能默默省略或塞到最后阶段。独立中性问题验证、真实失败证据交接、真实模型复测、跨需求关联及默认选型仍待完成。

验证记录保存在本机 `runs/event-supplements-20261117/`；新增 25 项回归覆盖目录/ZIP/清单、节点隔离、越权拒绝、真实本地 HTTP/公开 CLI、两版审计、评分来源和旧事件结果。全量 376 项测试通过（128.6 秒），源码编译、锁文件和差异检查通过；157 份历史文件只读审计通过。官方两个需求均仍有 2 个节点、4 份材料，本身没有额外文件，补充材料压力用例使用虚构夹具。本批没有真实员工派发、模型提取或 DeepSeek 新评分。
