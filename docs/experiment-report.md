## 工程验证

通过 `python3 -m unittest discover -s tests -v` 执行自动测试，30 项测试通过，涵盖以下可观察行为。

- 中文、空行和 CRLF 保持行号，对话消息编号能够回溯。
- 官方 ZIP 的阶段发现、缺失产物报错和评测标注隔离。
- 引用编号、逐字引文和字段级证据校验，重复结果拒绝。
- 本机 HTTP 服务返回受控响应，走真实 HTTP 客户端及 CLI 子进程。
- 429 的有限重试、401 立即失败、错误 JSON 一次修复、无效引用最终报错。
- verified 三步处理、artifact-only 输入限制及未知用量保留为空。
- 批量部分失败继续执行、失败样本恢复、配置变化阻止复用、结果修改被检测。
- 人工评测表保留未评状态，引用支持与内容准确分开记录，参考答案按唯一 ID 计覆盖。
- 中断的 chunked HTTP 响应经过有限重试后记为该样本失败，批次继续处理后续样本。
- 模型过滤、工具调用和缺失结束状态均返回错误。
- 修改 Markdown 交接文件会阻止断点复用，BOM 字节改变会改变原始文件哈希。

独立代码评审提出上述 HTTP 中断、完成状态、Markdown 完整性和原始字节指纹四项问题。已分别观察回归测试失败、修复实现，并运行完整测试集验证。

可编辑安装已验证。wheel 构建后在仓库外的独立虚拟环境安装，命令行入口能够读取同一个官方 ZIP。

## 评测口径

原始附件含人工标注，部分知识跨阶段组织。参考集应由评审者按当前阶段材料建立，再使用 `review init` 和 `review score` 填写判断与汇总结果。

本地 `precision_reviewed`、`recall` 和 `citation_support_reviewed` 为明确标注的自测指标。正式比赛的语义匹配、条目粒度与计分规则仍需以出题方说明为准。
